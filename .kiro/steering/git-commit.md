# กฎการเขียน Commit Message

เมื่อต้องสร้าง git commit message ให้เขียนเป็นภาษาไทยเสมอ

## รูปแบบ

- บรรทัดแรก (หัวข้อ): สรุปสิ่งที่เปลี่ยน ไม่เกิน 72 ตัวอักษร ไม่ต้องมีจุดท้ายประโยค
- เว้น 1 บรรทัด แล้วตามด้วยรายละเอียด (ถ้าจำเป็น) อธิบายว่าเปลี่ยนอะไรและเพราะอะไร
- ใช้คำกริยานำหน้า เช่น เพิ่ม, แก้ไข, ลบ, ปรับปรุง, ย้าย, เปลี่ยนชื่อ

## Prefix (ไม่บังคับ แต่ถ้าใช้ให้คงเป็นภาษาอังกฤษตามแบบ Conventional Commits)

- `feat:` ฟีเจอร์ใหม่
- `fix:` แก้บั๊ก
- `docs:` เอกสาร
- `refactor:` ปรับโครงสร้างโค้ดโดยไม่เปลี่ยนพฤติกรรม
- `test:` เพิ่มหรือแก้เทส
- `chore:` งานจิปาถะ เช่น config, dependency

## ข้อควรคงเป็นภาษาอังกฤษ

ชื่อไฟล์ ชื่อฟังก์ชัน ชื่อแพ็กเกจ และคำศัพท์เทคนิคที่ไม่มีคำแปลที่เป็นที่รู้จัก ให้คงไว้ตามเดิม

## ตัวอย่าง

```
feat: เพิ่มการส่งไฟล์ผ่าน WebSocket

เพิ่ม handler สำหรับรับไฟล์ใน httpapi และเชื่อมกับ usecase transfer
เพื่อให้อุปกรณ์ในเครือข่ายเดียวกันแชร์ไฟล์กันได้
```

```
fix: แก้ middleware ตรวจ token ไม่ผ่านเมื่อ header ว่าง
```
