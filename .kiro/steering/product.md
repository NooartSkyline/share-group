# ผลิตภัณฑ์: Share Group

Share Group คือเซิร์ฟเวอร์แชร์ไฟล์ในเครือข่ายท้องถิ่น (LAN) รันบนเครื่องโฮสต์ของเจ้าของ (วันนี้คือ Mac เป็น Go binary ตัวเดียว + เปลือก menu bar) อุปกรณ์อื่นเข้าร่วมผ่านเบราว์เซอร์ โดยสแกน QR code หรือเปิด URL แล้วกรอก PIN ไม่ต้องติดตั้งแอปลูกข่ายและไม่ต้องใช้อินเทอร์เน็ต

## แนวคิดหลัก
- **Room (ห้อง)**: พื้นที่แชร์ที่แยกขาดจากกัน มี PIN 6 หลัก ไฟล์ และรายชื่ออุปกรณ์ของตัวเอง ห้องหนึ่งมองไม่เห็นไฟล์ของอีกห้องเด็ดขาด
- **Device (อุปกรณ์)**: เซสชันของเบราว์เซอร์ ระบุตัวตนด้วย token ที่ออกให้หลังกรอก PIN ถูกต้อง
- **Roles (บทบาท)**: Owner, Member, Uploader (ผู้เยี่ยมชม อัปโหลดได้อย่างเดียว), Viewer (ดาวน์โหลดได้อย่างเดียว)
- **Real-time**: WebSocket ส่งสถานะอุปกรณ์ เหตุการณ์ไฟล์ ความคืบหน้าการโอน แชท และคลิปบอร์ด

## ฟีเจอร์
แคตตาล็อกเต็มอยู่ใน `docs/project-scope.md` หัวข้อ 12

- อัปโหลด/ดาวน์โหลดแบบ streaming สองทาง พร้อมแสดงความคืบหน้าและความเร็ว
- คลิปบอร์ดร่วมและข้อความแชทสั้นๆ (เก็บใน memory ห้องละ 200 ข้อความล่าสุด)
- ดาวน์โหลดหลายไฟล์เป็น zip (สูงสุด 500 ไฟล์), อัปโหลดโฟลเดอร์, thumbnail, วางรูปเพื่ออัปโหลด, จัดการชื่อไฟล์ซ้ำ
- PIN lockout เมื่อกรอกผิดซ้ำหลายครั้ง
- Resumable upload พร้อม auto-resume: อัปโหลดต่อจากจุดที่ค้างได้เองเมื่อเครือข่ายหลุดหรือ Mac รีสตาร์ท
- ตรวจความถูกต้องด้วย SHA-256 ทั้งสองฝั่ง (เบราว์เซอร์และเซิร์ฟเวอร์) และแสดงสถานะการตรวจของแต่ละไฟล์
- กันดิสก์เต็ม (disk guard) และกัน Mac หลับระหว่างมีการโอน (keep-awake)
- หน้า diagnostics สำหรับ Owner ตรวจปัญหาการเชื่อมต่อ (Firewall, Wi-Fi, อุปกรณ์ที่ต่อเข้ามา, session อัปโหลดที่ค้างอยู่)
- PWA และการแจ้งเตือนเมื่อมีไฟล์ใหม่ (ต้องใช้ Secure_Context ดูกฎของผลิตภัณฑ์)
- หลายห้อง, อนุมัติอุปกรณ์, ลิงก์แขก, โควตา/หมดอายุไฟล์, HTTPS ด้วย `-tls`
- ธีมมืด/สว่าง, ไทย/อังกฤษ, ค้นหาและจัดกลุ่มไฟล์
- CLI `share send`, สตรีมวิดีโอ/เพลง, Web Share Target, ย่อรูป, แปลง HEIC, syntax highlight, Shortcuts API, Finder Quick Action, แอป menu bar
- สาย USB: เข้าห้องโดยไม่ต้องมีเน็ต, Owner เรียกดูไฟล์บนเครื่องที่เสียบสาย (Android ผ่าน ADB ครบถ้วน, iPhone ดูได้เฉพาะแอปจาก Xcode)

## สถานะ (ดู `docs/project-scope.md` หัวข้อ 11 และ 12)
- Phase A–G เสร็จฝั่งโค้ดแล้ว
- Phase H (สาย USB และไฟล์บนเครื่อง) เสร็จฝั่งโค้ดแล้ว
- Phase I (โฮสต์ Windows / Android / iOS) เป็นแผนยังไม่ทำ สแตกที่ล็อก: แกน Go + แดชบอร์ด `web/` เดิม เปลือก Windows เป็น Go, Android เป็น Kotlin ห่อ Go, iOS เป็น Swift ห่อ Go ชั้น `domain`/`usecase` อยู่ที่ Go อย่างเดียว
- ค่าเริ่มต้นยังเป็น HTTP ธรรมดา เปิด `-tls` และเปิดอนุมัติอุปกรณ์ในหน้า Owner ก่อนให้คนอื่นที่ยังไม่ไว้ใจเชื่อมต่อ

## กฎของผลิตภัณฑ์
- ไฟล์ขนาดใหญ่ (หลาย GB) ต้อง stream ห้ามโหลดทั้งไฟล์เข้า RAM
- ทุกการทำงานต้องอยู่ในขอบเขตของ `RoomID` และตรวจสิทธิ์ตามบทบาท ห้องหนึ่งมองไม่เห็นไฟล์ของอีกห้อง
- UI ที่ผู้ใช้เห็นและแบนเนอร์ตอนเริ่มระบบเป็นภาษาไทยเป็นค่าเริ่มต้น สลับเป็นอังกฤษได้ในตั้งค่า ข้อความใหม่ที่แสดงต่อผู้ใช้ต้องใช้ภาษาให้สอดคล้องกับของเดิม
- Resume_Key ของ Upload_Session เป็นความลับเทียบเท่า PIN และ token: ห้าม log (รวม header และ query string), ห้ามแสดงในหน้า Owner หรือ diagnostics, ส่งคืนให้ client ครั้งเดียวตอนสร้าง session
- PWA, Service Worker และการแจ้งเตือนต้องใช้ Secure_Context (HTTPS หรือ `localhost`) บนอุปกรณ์อื่นผ่าน HTTP ธรรมดาฟีเจอร์เหล่านี้จะไม่ทำงาน และต้องไม่ทำให้ส่วนอื่นของแอปพัง เปิด HTTPS ด้วย `-tls` เมื่อต้องการ Secure_Context บน IP ของ LAN
- `docs/project-scope.md` (ภาษาไทย) เป็นแหล่งอ้างอิงหลักของขอบเขต เฟส แคตตาล็อกฟีเจอร์ (หัวข้อ 12) ภาพรวมระบบ (13) ข้อมูลนักพัฒนา (14) และต้นแบบ UI (15) ต้นแบบปัจจุบันคือ `mock/ui-mock-v3.html` ไม่ต่อเซิร์ฟเวอร์
