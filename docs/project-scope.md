## 1. วัตถุประสงค์

สร้างโปรแกรมแชร์ไฟล์ที่ทำงานภายในวง LAN เดียวกัน ให้อุปกรณ์ทุกแพลตฟอร์ม (Android, iOS, Windows, macOS) ส่งและรับไฟล์ระหว่างกันได้ทั้งสองทิศทาง โดยไม่ต้องติดตั้งแอปบนฝั่งผู้ใช้ปลายทางและไม่ต้องผ่านอินเทอร์เน็ต รองรับการใช้งานร่วมกับคนอื่นและแยกเป็นหลายทีมได้

## 2. การตัดสินใจที่ยืนยันแล้ว

| หัวข้อ | การตัดสินใจ | ผลต่อแผน |
|---|---|---|
| กลุ่มผู้ใช้ | ใช้กับคนอื่นและหลายทีม | ห้องแชร์, สิทธิ์, โหมดแขก, การอนุมัติอุปกรณ์ และ HTTPS กลายเป็นฟีเจอร์หลัก (ย้ายจาก Phase F มาเป็น Phase A/D) |
| รูปแบบการติดตั้ง (วันนี้) | ติดตั้งโฮสต์บน Mac / Android / Windows จาก `dist/<เวอร์ชัน>/` คนอื่นเข้าผ่านเบราว์เซอร์ iOS build จาก Xcode | ไฟล์ยังไม่ลงนาม ไม่มีระบบอัปเดตอัตโนมัติ รุ่นเก่าเก็บใน `dist/` แยกโฟลเดอร์ |
| โฮสต์เพิ่ม (Phase I) | แกน Go ก้อนเดียวทุกเครื่อง แดชบอร์ด `web/` เดิม เปลือกเนทีฟบาง ๆ: Windows เป็น Go ทั้งก้อน, Android เป็น Kotlin ห่อ Go, iOS เป็น Swift ห่อ Go หน้าตายึด Mac ชั้นโค้ดยังเป็น Clean Architecture | ลูกข่ายยังใช้เบราว์เซอร์ ไม่เขียนเซิร์ฟเวอร์ซ้ำใน Kotlin/Swift/C# ไม่ใช้ Flutter |
| รูปแบบแอปฝั่ง Mac | แอป menu bar ด้วย Swift AppKit (LSUIElement) เรียกเซิร์ฟเวอร์ Go | Wails v3 ยังเป็น alpha จึงใช้เปลือก Swift แทน หน้าแดชบอร์ดยังเป็นเว็บเดิม |
| PIN ต่อห้อง | 6 หลัก | มี 1,000,000 แบบ เดายากกว่า 4 หลัก 100 เท่า ยังคงมีการล็อกเมื่อกรอกผิด |
| ภาษาเซิร์ฟเวอร์ | Go | เน้นความเสถียรและการจัดการการเชื่อมต่อพร้อมกัน แกนหลักเป็นไบนารีเดียว |
| ไลบรารี WebSocket | `coder/websocket` | อยู่หลัง port `EventPublisher` เปลี่ยนภายหลังได้ |
| สถาปัตยกรรม | Clean Architecture | แยกชั้น domain / usecase / adapter / infra (ดูหัวข้อ 3.4) |

เหตุผลที่เลือก Go: ความเร็วถ่ายโอนส่วนใหญ่ถูกจำกัดโดย Wi-Fi และดิสก์ ไม่ใช่ภาษา จึงเลือกจากความเสถียรเป็นหลัก ข้อสรุปนี้มาจากลักษณะของเครื่องมือ ยังไม่ได้วัดประสิทธิภาพจริงกับโปรเจกต์นี้

## 3. แนวทางทางเทคนิค

### 3.1 ภาพรวม

วันนี้ MacBook รันเซิร์ฟเวอร์ในเครื่อง ส่วนเครื่องอื่นเปิดหน้าเว็บผ่านเบราว์เซอร์ Phase I เพิ่มโฮสต์ Windows / Android / iOS โดยใช้แกน Go ก้อนเดียวกัน แดชบอร์ด `web/` เดิม และเปลือกเนทีฟบาง ๆ (ดูหัวข้อ 4)

```
 Android ─┐
 iPhone  ─┼──── Wi-Fi เดียวกัน ────►  MacBook (เซิร์ฟเวอร์ Go :8080)
 Windows ─┘         หรือสาย USB       ├─ ห้องแชร์ (room) แต่ละห้องแยกไฟล์/สิทธิ์
                                      ├─ รับอัปโหลด / ส่งดาวน์โหลด (HTTP stream)
                                      ├─ เรียกดูไฟล์บนมือถือที่เสียบสาย (Owner)
                                      └─ แจ้งสถานะเรียลไทม์ (WebSocket)
```

### 3.3 ลำดับการทำงาน

1. Mac เปิดเซิร์ฟเวอร์ที่ `0.0.0.0:8080` แล้วแสดง URL, QR code และ PIN ของห้อง
2. อุปกรณ์อื่นสแกน QR หรือพิมพ์ URL แล้วกรอก PIN เพื่อรับ token และเข้าห้องนั้น
3. เบราว์เซอร์เปิด WebSocket ค้างไว้ เพื่อลงทะเบียนอุปกรณ์และรับการแจ้งเตือน
4. ส่งไฟล์ไป Mac ด้วย HTTP `POST` แบบ stream เขียนลงดิสก์ทีละชิ้น
5. ส่งไฟล์จาก Mac โดยวางไฟล์ในห้อง เครื่องปลายทางดาวน์โหลดด้วย HTTP `GET`
6. การส่งระหว่างมือถือด้วยกันจะผ่าน Mac เป็นตัวกลาง

### 3.4 Clean Architecture

หลักการ (Dependency Rule): ชั้นนอกรู้จักชั้นใน แต่ชั้นในไม่รู้จักชั้นนอก

```
 cmd (composition root)
   └─► adapter  ──►  usecase  ──►  domain
        │               ▲
        └─► infra ──────┘ (implement port ที่ usecase กำหนด)
```

| ชั้น | หน้าที่ | พึ่งพาอะไรได้ |
|---|---|---|
| `domain` | Entity และกฎธุรกิจล้วนๆ เช่น Room, Device, File, Transfer, Pin, Role | ไม่พึ่งใครเลย (ไม่มี HTTP, ไม่มี SQL) |
| `usecase` | กรณีใช้งาน เช่น เข้าห้องด้วย PIN, เริ่มอัปโหลด, ดาวน์โหลด พร้อมประกาศ port (interface) ที่ต้องใช้ | `domain` เท่านั้น |
| `adapter` | HTTP handler, WebSocket hub, repository (SQLite), file store, ตัวดึงข้อมูลเครือข่าย | `usecase`, `domain` |
| `infra` / `cmd` | config, logger, TLS, การต่อสาย dependency ทั้งหมด (`main`) | ทุกชั้น |

โครงสร้างโฟลเดอร์ที่วางแผนไว้

```
share-group/
├── cmd/
│   └── lanshare/              # CLI: โหลด flag แล้วเรียก internal/app
├── internal/
│   ├── domain/                # room.go device.go file.go transfer.go pin.go role.go errors.go
│   ├── usecase/
│   │   ├── port/              # interface: RoomRepository, DeviceRepository, FileStore,
│   │   │                      #   EventPublisher, TokenService, RateLimiter, Clock, NetworkProvider
│   │   ├── auth/              # เข้าห้องด้วย PIN, ล็อกเมื่อกรอกผิด, ออก token
│   │   ├── room/              # สร้าง/จัดการห้องและสิทธิ์
│   │   ├── device/            # ลงทะเบียน/อนุมัติ/รายการอุปกรณ์ออนไลน์
│   │   └── transfer/          # อัปโหลด/ดาวน์โหลดแบบ stream, progress
│   ├── adapter/
│   │   ├── httpapi/           # router, handler, middleware, DTO
│   │   ├── ws/                # WebSocket hub
│   │   ├── sqlite/            # implement repository
│   │   ├── filestore/         # implement FileStore บนดิสก์
│   │   └── netinfo/           # implement NetworkProvider (net.Interfaces)
│   └── infra/                 # config, logger, tls
├── web/                       # หน้าเว็บ (ฝังด้วย embed)
├── desktop/
│   ├── LanShareMenu/          # เปลือก menu bar บน Mac (Swift AppKit, Phase G)
│   └── windows/               # เปลือกถาดระบบ Windows (Go) เปิด/ปิด lanshare.exe แดชบอร์ดในเบราว์เซอร์ คลิกขวา Explorer
├── mobile/
│   ├── android/               # เปลือก Kotlin + WebView + foreground service (Phase I)
│   └── ios/                   # เปลือก Swift + WKWebView ห่อ xcframework (Phase I ใช้ได้ตอนแอปเปิดอยู่)
├── docs/
└── mock/
```

ข้อกำหนดของการออกแบบ

- **Port อยู่ฝั่งผู้ใช้:** interface ถูกประกาศในชั้น `usecase/port` ไม่ใช่ที่ชั้น implement ตามแนวทางปกติของ Go
- **ไฟล์ต้องเป็น stream เสมอ:** port ของ `FileStore` และ use case ของการถ่ายโอนรับ `io.Reader` / `io.Writer` ห้ามอ่านทั้งไฟล์เข้า RAM เพื่อให้ส่งไฟล์หลาย GB ได้
- **โมเดลห้องมีตั้งแต่ Phase A:** ทุก use case รับ `RoomID` และตรวจสิทธิ์ตั้งแต่แรก แม้ช่วงแรกจะมีห้องเริ่มต้นห้องเดียว เพื่อไม่ต้องรื้อทีหลัง
- **ไม่ให้ domain รู้จัก JSON/SQL:** แปลงข้อมูลที่ชั้น adapter ผ่าน DTO และ mapper
- **การทดสอบ:** unit test ของ domain และ usecase ใช้ fake ที่ implement port ไม่ต้องใช้ HTTP หรือดิสก์จริง ส่วน adapter ทดสอบด้วย `httptest` และ integration test
- **เปลือกโฮสต์ไม่ใช่ที่ใส่กฎธุรกิจ:** Kotlin / Swift / ถาด Windows ทำได้แค่เปิด-ปิดเซิร์ฟเวอร์, การแจ้งเตือน, Hotspot, ที่เก็บเครื่อง, OTG ห้อง PIN ไฟล์ สิทธิ์ อยู่ที่ `usecase` ผ่าน port เหมือนบน Mac ความสามารถของ OS เครื่องใหม่เพิ่มเป็น port ใน `usecase/port` แล้ว implement ใน `adapter` ห้าม copy กฎไปไว้ในแอปเนทีฟ

### 3.5 โมเดลห้องและสิทธิ์ (รองรับหลายทีม)

| บทบาท | สิทธิ์ |
|---|---|
| Owner | จัดการห้อง, อนุมัติอุปกรณ์, ลบไฟล์, เปลี่ยน PIN |
| Member | อัปโหลดและดาวน์โหลดไฟล์ในห้อง |
| Uploader | อัปโหลดอย่างเดียว (ใช้กับโหมดแขก) |
| Viewer | ดาวน์โหลดอย่างเดียว |

แต่ละห้องมี PIN, โฟลเดอร์ไฟล์ และรายชื่ออุปกรณ์ของตัวเอง ห้องหนึ่งมองไม่เห็นไฟล์ของอีกห้อง

## 4. ขอบเขตงาน (In Scope)

### Phase A: โครงสร้างหลักและ MVP (ประมาณ 5-8 วัน)

- วางโครงสร้าง Clean Architecture, ระบบต่อ dependency และชุดทดสอบ
- **โมเดลห้อง/อุปกรณ์/บทบาท** พร้อมการแยกไฟล์ตามห้อง (ใช้ห้องเริ่มต้นห้องเดียวก่อน)
- เซิร์ฟเวอร์ในเครื่อง, หา IP, สร้าง QR code, PIN และ token
- **PIN 6 หลักต่อห้อง และล็อกเมื่อกรอกผิดหลายครั้ง** (จำกัดจำนวนครั้งต่อช่วงเวลา แม้ PIN 6 หลักจะเดายากกว่า แต่ยังต้องกันการลองซ้ำ)
- **เลือกการ์ดเครือข่ายที่ใช้เปิดเซิร์ฟเวอร์** (Wi-Fi, Ethernet, VPN) เพื่อให้ URL และ QR ชี้ไปที่ IP ที่เครื่องอื่นเข้าถึงได้จริง
- รายการอุปกรณ์ที่ออนไลน์แบบเรียลไทม์
- อัปโหลดและดาวน์โหลดสองทิศทางแบบ stream พร้อม progress และความเร็ว
- UI เว็บ (dashboard บน Mac และหน้ามือถือ) รองรับลากวางและเลือกหลายไฟล์

### Phase B: ใช้งานสะดวกขึ้น (ประมาณ 2.75-4 วัน)

- คลิปบอร์ดร่วม
- แชร์ข้อความสั้น
- ดาวน์โหลดหลายไฟล์เป็น zip
- ส่งโฟลเดอร์
- ตัวอย่างรูปและวิดีโอ (thumbnail)
- **วางภาพหรือสกรีนช็อตจากคลิปบอร์ดลงหน้าเว็บ** (Ctrl/Cmd+V) แล้วส่งได้ทันที
- **จัดการไฟล์ชื่อซ้ำ**: ข้าม เขียนทับ หรือเปลี่ยนชื่ออัตโนมัติ

### Phase C: ความเสถียร (ประมาณ 3.5-4.5 วัน)

- Resumable upload (ต่อจากเดิมเมื่อ Wi-Fi หลุด)
- **ตรวจความถูกต้องของไฟล์ด้วย SHA-256** หลังส่งเสร็จ เพื่อยืนยันว่าไฟล์ไม่เสียหาย
- กัน Mac หลับระหว่างถ่ายโอน (`caffeinate`)
- หน้าตรวจปัญหาการเชื่อมต่อ (Firewall, AP Isolation, คำแนะนำ 2.4GHz/5GHz)
- PWA และการแจ้งเตือนไฟล์ใหม่
- ตรวจพื้นที่ดิสก์ก่อนรับไฟล์

### Phase D: หลายทีมและความปลอดภัย (ประมาณ 4.5-6 วัน)

ต้องทำก่อนเปิดให้คนอื่นเชื่อมต่อเข้ามาที่ Mac

- **หน้าจัดการห้อง**: สร้างหลายห้อง, ตั้ง PIN 6 หลักแยกต่อห้อง, กำหนดบทบาทของแต่ละอุปกรณ์
- **โหมดแขก**: ลิงก์ชั่วคราว อัปโหลดอย่างเดียว (บทบาท Uploader)
- Mac อนุมัติอุปกรณ์ใหม่, จำอุปกรณ์ที่เคยเชื่อมต่อ, ตั้งชื่ออุปกรณ์
- ไฟล์หมดอายุอัตโนมัติ
- จำกัดขนาดโฟลเดอร์แชร์ต่อห้อง และลบไฟล์จากหน้าเว็บ
- HTTPS แบบ self-signed

### Phase E: ประสบการณ์ใช้งาน (ประมาณ 1.5-2.5 วัน)

- โหมดมืด/สว่าง
- ภาษาไทยเป็นค่าเริ่มต้น สลับได้ 16 ภาษา (ไทย อังกฤษ จีน สเปน ฮินดี อาหรับ ฝรั่งเศส โปรตุเกส รัสเซีย ญี่ปุ่น เยอรมัน เกาหลี เบงกาลี อินโดนีเซีย ลาว เขมร)
- ค้นหาและกรองไฟล์
- จัดไฟล์อัตโนมัติตามอุปกรณ์และวันที่

### Phase F: ฟีเจอร์ขั้นสูง (ประมาณ 3.5-5.5 วัน)

- **สตรีมวิดีโอและเพลงจาก Mac ไปเล่นบนมือถือ** ผ่าน HTTP range request โดยไม่ต้องดาวน์โหลดทั้งไฟล์
- แปลง HEIC เป็น JPG อัตโนมัติ (บน macOS เรียกใช้เครื่องมือ `sips` ของระบบได้ ไม่ต้องพึ่ง cgo)
- ย่อรูปก่อนส่ง
- Web Share Target บน Android
- CLI (`share send <file>`)
- Finder Quick Action
- HTTP API สำหรับ Shortcuts และ automation
- แชร์โค้ดพร้อม syntax highlight

### Phase G: แอป Mac แบบ menu bar (ประมาณ 2.5-4 วัน)

- เปลือกแอป menu bar ด้วย Swift AppKit (`LSUIElement`) ที่เปิด/ปิดเซิร์ฟเวอร์ Go (ไม่ใช้ Wails เพราะ v3 ยังเป็น alpha)
- เมนูจากไอคอนบน menu bar แสดง PIN, ห้องปัจจุบัน, การ์ดเครือข่าย, จำนวนอุปกรณ์ และอุปกรณ์ที่รออนุมัติ
- หน้าต่าง Dashboard เต็มรูปแบบเปิดจากเมนู ใช้หน้าเว็บเดียวกับที่ฝังในเซิร์ฟเวอร์
- เปิดอัตโนมัติเมื่อเข้าสู่ระบบ (LaunchAgent) และซ่อนไอคอนจาก Dock
- สร้างและรันบน Mac ของเจ้าของเครื่องเท่านั้น จึงไม่ต้อง sign/notarize หรือทำระบบอัปเดตอัตโนมัติ (ถ้าภายหลังจะแจกแอปให้คนอื่นติดตั้ง ค่อยเพิ่ม)

### Phase H: สาย USB และไฟล์บนเครื่อง (ทำเพิ่มหลังแผนเดิม)

- มือถือเสียบสายเข้า Mac แล้วเข้าเซิร์ฟเวอร์ตัวเดียวกับ Wi-Fi ได้โดยไม่ต้องมีเน็ต
- Owner เปิดหน้าห้องบนมือถือจากแดชบอร์ด (Android ใช้ `adb reverse` + intent, iPhone ใช้ลิงก์/QR หรือพยายามเปิด Safari)
- Owner เรียกดูไฟล์บนเครื่องที่เสียบสายตอนนี้เท่านั้น: เลือกแบบ Finder, พรีวิว, บันทึกลง Mac, ดึงเข้าห้อง
- Android ที่เปิด USB debugging: คัดลอก ตัด วางบนเครื่องเดียวกันหรือข้ามสาย, สร้างโฟลเดอร์แล้วเปิดให้วาง, ลบ, สำเนาแอป (APK ข้ามเครื่อง)
- iPhone: เรียกดูได้เฉพาะคอนเทนเนอร์ของแอปที่ติดตั้งจาก Xcode ไม่ลบหรือสร้างโฟลเดอร์ผ่านสาย

เพิ่มโฮสต์ใหม่ตามนี้ ต้นแบบผิว: [`mock/ui-mock-hosts.html`](../mock/ui-mock-hosts.html)

#### สแตก (ล็อกแล้ว)

แกนเดียวกับ Mac: `internal/` (Clean Architecture) + `web/` ฝังในไบนารี Go เปลือกเนทีฟบาง ๆ เรียก Start/Stop และอ่าน `localhost` เหมือน `desktop/LanShareMenu` เรียกเซิร์ฟเวอร์ Go

| เครื่อง | แกน | เปลือก OS | แดชบอร์ด | ข้อจำกัด |
|---|---|---|---|---|
| Windows | Go (`GOOS=windows`) | ถาดระบบเป็น Go ใน `desktop/windows` Explorer เทียบ Finder เป็นส่วนเสริมเล็ก | `web/` ในหน้าต่างโลคอล | ไม่แปลง HEIC/`sips`; ไม่เขียนเซิร์ฟเวอร์เป็น C# |
| Android | ไลบรารี Go (`gomobile` / xcframework ฝั่ง Android) | Kotlin ใน `mobile/android`: foreground service, Hotspot, SAF, OTG | `web/` ใน WebView ที่ `http://127.0.0.1:<port>` | ไม่เรียกดู iPhone ผ่านสาย |
| iOS | ไลบรารี Go (xcframework) | Swift ใน `mobile/ios`: เปิดแอปค้าง, Local Network, WKWebView | `web/` ที่ `http://127.0.0.1:<port>` | ใช้ได้ตอนแอปเปิดอยู่ ไม่มีไฟล์บนเครื่อง / OTG ตามขอบเขต iOS |

ลำดับทำ: Windows (Go ล้วน) → Android (Kotlin ห่อ Go) → iOS (Swift ห่อ Go)

ห้าม: เขียนเซิร์ฟเวอร์ซ้ำใน Kotlin / Swift / C#, Flutter, แดชบอร์ดคนละชุดจาก `web/`

#### Clean Architecture บนโฮสต์ใหม่

ชั้น `domain` / `usecase` / `usecase/port` ไม่เปลี่ยนและไม่มี `#ifdef` ตาม OS ความต่างของเครื่องอยู่ที่ adapter กับเปลือกเท่านั้น

```
เปลือกเนทีฟ (Kotlin / Swift / ถาด Windows)
    │  เปิด-ปิด, แจ้งเตือน, Hotspot, ที่เก็บเครื่อง, OTG
    ▼
cmd (composition root) ประกอบ adapter ของ OS นั้น
    │
adapter (httpapi, filestore, netinfo, และ adapter เฉพาะเครื่อง)
    │  implement port
    ▼
usecase  ←  port ประกาศที่ usecase/port เท่านั้น
    │
domain
```

พอร์ตที่มีแล้วใช้ต่อ ไม่สร้างชื่อใหม่ถ้ายังไม่จำเป็น:

- `NetworkProvider` — เลือกการ์ด / Hotspot / Wi-Fi ตามเครื่อง
- `FileStore` — ไฟล์ในห้องบนดิสก์ของโฮสต์
- `ActivityTracker` + `CaffeinateLauncher` — กันเครื่องหลับระหว่างโอน (Mac ใช้ `caffeinate`; Windows / Android / iOS ใส่ adapter คนละตัวที่ implement port เดิม)
- `HEICConverter` / `SystemPreviewer` — บน macOS เป็น `sips`/`qlmanage`; เครื่องอื่นคืน `ErrUnsupported` ไม่ copy กฎไป Kotlin/Swift

พอร์ตที่เพิ่มเมื่อมีผู้ใช้จริง (ห้ามสร้างว่าง ๆ ล่วงหน้า ตามกฎใน `structure.md`): ที่เก็บในเครื่องโฮสต์ Android และ USB OTG ใช้ `port.HostBrowser` (`internal/adapter/hostfs`) เชื่อมใน `internal/app` แล้วเรียกจากแท็บไฟล์บนเครื่อง รวมคัดลอก/วาง และโฟลเดอร์เพิ่มจาก SAF (`host-roots.json`) สถานะ Hotspot ยังไม่เพิ่ม port แยก — ติดป้ายที่ `NetworkProvider` เปลือก Android เปิดหน้าตั้งค่า Hotspot ของระบบจากปุ่มในแจ้งเตือน

แอป Kotlin/Swift ห้าม import กฎห้อง ห้ามเก็บ PIN/token ใน UI state เป็นแหล่งความจริง แหล่งความจริงอยู่ที่ Go ผ่าน HTTP บน `127.0.0.1` เหมือน Owner บน Mac

โปรแกรมที่รันวันนี้ยังเป็นโฮสต์ Mac เป็นค่าเริ่มต้น โฮสต์อื่นใช้แกน Go ก้อนเดียวกัน

| เรื่อง | สถานะ |

| Android (Samsung SM-S911B) | Owner, QR/PIN/Wi-Fi, อนุมัติ/ถอด, แชท, อัปโหลด, แท็บไฟล์บนเครื่อง, ตัวเลือกไฟล์ในแท็บถ่ายโอน, resume 4 MiB หลังปิดแอป, ฮอตสปอตเป็น NIC (`swlan0` ติดป้าย Hotspot เครื่องอื่นเข้า `http://<ip>:8080/?r=main` ได้) |

## 5. นอกขอบเขต (Out of Scope)

ยังไม่รวมในแผนนี้ และพิจารณาภายหลังได้

- แอปเนทีฟฝั่งลูกข่าย และการค้นหาอุปกรณ์อัตโนมัติด้วย mDNS (แอปโฮสต์ Android/iOS อยู่ใน Phase I)
- การใช้งานผ่านอินเทอร์เน็ตหรือข้ามเครือข่าย
- ระบบบัญชีผู้ใช้และการเก็บไฟล์บนคลาวด์
- โฮสต์บน Linux (Windows / Android / iOS อยู่ใน Phase I โปรแกรมที่รันวันนี้ยังเป็น macOS)

## 6. ข้อจำกัดและข้อสมมติฐาน

- ทุกอุปกรณ์ต้องอยู่ใน Wi-Fi/LAN เดียวกัน และ router ต้องไม่เปิด AP Isolation
- macOS Firewall ต้องอนุญาตการเชื่อมต่อขาเข้าให้โปรแกรม
- iOS Safari เลือกโฟลเดอร์ปลายทางเองไม่ได้ ไฟล์จะไปที่แอป Files หรือ Photos
- ฝั่งมือถือต้องกดดาวน์โหลดเองทีละไฟล์ ส่งเข้าเครื่องอัตโนมัติไม่ได้
- เบราว์เซอร์ค้นหาอุปกรณ์อัตโนมัติไม่ได้ ต้องสแกน QR หรือพิมพ์ URL
- Web Share Target รองรับเฉพาะ Android (ผ่าน PWA)
- ค่าเริ่มต้นยังเป็น HTTP ธรรมดา เปิด HTTPS ด้วย `-tls` และเปิดอนุมัติอุปกรณ์ในหน้า Owner ก่อนให้คนอื่นที่ยังไม่ไว้ใจเชื่อมต่อ
- Service Worker, การติดตั้งเป็น PWA และการแจ้งเตือนของระบบต้องใช้ Secure_Context (HTTPS หรือ `localhost`) ตราบที่ยังเป็น HTTP ธรรมดา ฟีเจอร์เหล่านี้ใช้ได้เฉพาะบน Mac เจ้าของเครื่องที่เปิดผ่าน `localhost` จนกว่าจะทำ HTTPS ใน Phase D (ดู "ข้อจำกัดที่ทราบ" ในหัวข้อ 11)
- ติดตั้งแอปเฉพาะ Mac ของเจ้าของเครื่อง คนอื่นใช้งานผ่านเบราว์เซอร์ จึงไม่ต้องติดตั้งอะไร

## 7. ความเสี่ยง

| ความเสี่ยง | ผลกระทบ | แนวทางรับมือ |
|---|---|---|
| Router เปิด AP Isolation | เครื่องมองไม่เห็นกัน | หน้าตรวจปัญหาและคำแนะนำ (Phase C) |
| Firewall บน Mac บล็อกพอร์ต | เชื่อมต่อไม่ได้ | แจ้งผู้ใช้ให้อนุญาต และมีคำแนะนำในหน้าตรวจปัญหา |
| ไฟล์ใหญ่หลาย GB ขาดกลางทาง | ต้องเริ่มส่งใหม่ | Stream upload และ resumable upload |
| Mac เข้าโหมดหลับระหว่างถ่ายโอน | การถ่ายโอนล้มเหลว | `caffeinate` ระหว่างมีงานถ่ายโอน |
| ใครก็เข้าถึงได้ใน Wi-Fi เดียวกัน | ไฟล์รั่วไหลหรือถูกอัปโหลดไฟล์ไม่พึงประสงค์ | PIN, token, อนุมัติอุปกรณ์ใหม่, HTTPS |
| เดา PIN 6 หลักด้วยการลองซ้ำ | เข้าถึงระบบโดยไม่ได้รับอนุญาต | ล็อกเมื่อกรอกผิดหลายครั้ง (Phase A) |
| ทีมหนึ่งเห็นไฟล์ของอีกทีม | ข้อมูลรั่วข้ามห้อง | ทุก use case ตรวจ `RoomID` และสิทธิ์, แยกโฟลเดอร์ต่อห้อง, ทดสอบการแยกห้องโดยเฉพาะ (Phase A) |
| Mac ต่อหลายเครือข่าย (Wi-Fi, Ethernet, VPN) | URL และ QR ชี้ IP ผิด เครื่องอื่นเข้าไม่ได้ | ให้เลือกการ์ดเครือข่ายเอง (Phase A) |

## 9. เกณฑ์ความสำเร็จของ MVP (Phase A)

- เปิดเซิร์ฟเวอร์ด้วยคำสั่งเดียวบน Mac แล้วเห็น URL, QR และ PIN
- iPhone, Android และ Windows เข้าใช้งานผ่านเบราว์เซอร์ได้โดยไม่ติดตั้งแอป
- ส่งไฟล์จากอุปกรณ์ใดก็ได้ไป Mac และจาก Mac ไปอุปกรณ์ใดก็ได้
- ส่งไฟล์ขนาดอย่างน้อย 1 GB ได้โดยไม่ใช้ RAM เพิ่มตามขนาดไฟล์
- เห็น progress และความเร็วแบบเรียลไทม์ทั้งสองฝั่ง
- อุปกรณ์ที่ไม่มี PIN ที่ถูกต้องเข้าถึงไฟล์ไม่ได้
- กรอก PIN ผิดเกินจำนวนที่กำหนดแล้วถูกล็อกชั่วคราว
- เลือกการ์ดเครือข่ายได้ และ URL/QR เปลี่ยนตามที่เลือก
- โค้ดแยกชั้นตาม Clean Architecture: ชั้น `domain` และ `usecase` ไม่ import แพ็กเกจ HTTP, SQL หรือระบบไฟล์ และมี unit test ที่ใช้ fake แทน port
- ไฟล์ของห้องหนึ่งถูกเข้าถึงจากอีกห้องไม่ได้ (มีเทสต์ยืนยัน)

### รายละเอียด Phase B ที่ทำจริง

- **คลิปบอร์ดร่วมและข้อความ:** เก็บในหน่วยความจำ (ล่าสุด 200 ข้อความต่อห้อง) จึงหายเมื่อรีสตาร์ตเซิร์ฟเวอร์ ส่งได้เฉพาะบทบาท Owner และ Member, อ่านได้ถึง Viewer, บทบาท Uploader (แขก) เข้าถึงไม่ได้
- **ดาวน์โหลดเป็น zip:** เลือกหลายไฟล์ได้สูงสุด 500 ไฟล์ต่อครั้ง สตรีมโดยไม่เก็บทั้งก้อนในหน่วยความจำ ไม่บีบอัด (เน้นความเร็วใน LAN) และรักษาโครงสร้างโฟลเดอร์
- **ส่งโฟลเดอร์:** รองรับการลากโฟลเดอร์และปุ่มเลือกโฟลเดอร์บนเบราว์เซอร์คอมพิวเตอร์ (มือถือเลือกโฟลเดอร์ไม่ได้) เก็บพาธไว้ในเมทาดาทา ไม่ได้สร้างโฟลเดอร์จริงบนดิสก์
- **ตัวอย่างไฟล์:** รูป JPEG, PNG, GIF, WebP สร้าง thumbnail ฝั่งเซิร์ฟเวอร์ด้วย decoder ของ Go (แก้ทิศทางตาม EXIF และกัน decompression bomb) แล้วแคชไว้ ส่วนวิดีโอใช้เฟรมแรกที่เบราว์เซอร์สร้างเอง รูป HEIC/เอกสารใช้ `sips`/`qlmanage` ของ macOS (Phase F)
- **วางภาพจากคลิปบอร์ด:** กด ⌘V หรือ Ctrl+V บนเบราว์เซอร์คอมพิวเตอร์ แล้วอัปโหลดเป็นไฟล์ "สกรีนช็อต วันที่ เวลา"
- **ไฟล์ชื่อซ้ำ:** ถามทุกครั้ง, เก็บทั้งสองไฟล์ (ค่าเริ่มต้นของเซิร์ฟเวอร์), เขียนทับ หรือข้าม และเลือก "ทำแบบนี้กับไฟล์ที่เหลือ" ได้ การเขียนทับทำได้เฉพาะไฟล์ที่ตัวเองส่งหรือเจ้าของห้อง
- **หน้าตา:** ปรับตาม UI v2 ใน Phase นี้ ได้แก่ sidebar อุปกรณ์และเมนู, แท็บล่างบนมือถือ, การ์ดไฟล์พร้อม thumbnail และการเลือกหลายไฟล์

แผน UI v2 ที่เคยค้าง (หลายห้อง, แบนเนอร์อนุมัติอุปกรณ์, ค้นหา/กรองไฟล์, ปุ่มหยุด/ต่อ, ป้าย SHA-256, หน้าตรวจปัญหา) ทำครบแล้วใน Phase C–E ส่วนสาย USB อยู่ Phase H

### รายละเอียด Phase C ที่ทำจริง

โค้ดของ Phase C ครบแล้ว แต่ยังไม่ได้ทดสอบบนอุปกรณ์จริง (ดู "ข้อจำกัดที่ทราบ" และ "สิ่งที่ผู้ใช้ต้องตรวจเอง" ด้านล่าง)

**อัปโหลดที่ต่อได้ (resumable upload)**

- อัปโหลดแบบ session: `POST /api/uploads` สร้าง session แล้วได้ `id` กับ Resume_Key (คืนให้ครั้งเดียว) จากนั้นเบราว์เซอร์ส่งไฟล์เป็นก้อน `PATCH /api/uploads/{id}?offset=N` ทีละ request (ก้อนละไม่เกิน 16 MiB ฝั่งเบราว์เซอร์) เซิร์ฟเวอร์เขียนต่อท้ายไฟล์ชั่วคราวใต้ `partial/` ได้เฉพาะเมื่อ offset ตรงกับที่ยืนยันไว้ ถ้าไม่ตรงตอบ 409 พร้อม offset ที่ถูกต้อง
- ถามตำแหน่งที่ส่งถึงแล้วด้วย `GET /api/uploads/{id}` (ได้ `offset`, `size`, เวลาหมดอายุ และ `sha256` ของไบต์ `[0, offset)`) ปิดงานด้วย `POST /api/uploads/{id}/complete` (ครั้งแรก 201 เรียกซ้ำภายใน 10 นาทีได้ 200 ไฟล์เดิม) ยกเลิกด้วย `DELETE /api/uploads/{id}`
- ไฟล์ที่ยังส่งไม่ครบไม่โผล่ในรายการไฟล์ ไม่มี thumbnail และไม่ดาวน์โหลดได้ จนกว่าจะ complete สำเร็จ แล้วจึงย้ายเข้าโฟลเดอร์ของห้องและส่ง event `file.added`
- Resume_Key ส่งทาง header `X-Resume-Key` เท่านั้น (ไม่อยู่ใน URL) เซิร์ฟเวอร์เก็บเฉพาะค่าแฮช SHA-256 ใน `sessions/<id>.json` ไม่เก็บ key ดิบ session ที่ไม่พบ อยู่ห้องอื่น หมดอายุ หรือ key ผิด ตอบ 404 เหมือนกันทุกกรณี
- เซิร์ฟเวอร์บันทึก offset ลงดิสก์ (`sessions/` สิทธิ์ `0o600`, `partial/` โฟลเดอร์ `0o700`) และตอบ offset เฉพาะค่าที่บันทึกแล้ว จึงต่อได้แม้เซิร์ฟเวอร์รีสตาร์ต เมื่อเริ่มระบบจะกู้ session จากดิสก์ (`Recover`) ตัดไฟล์ที่ยาวเกิน offset และลบ session ที่เสียหรือไฟล์หาย
- จำกัด session ที่ค้างอยู่ 16 รายการต่ออุปกรณ์ และ 64 รายการต่อห้อง session ที่ไม่มีความเคลื่อนไหวเกิน `-upload-ttl` ถูกลบอัตโนมัติ (ตรวจทุก 1 นาที)
- ถ้าไม่มีข้อมูลเข้ามานานเกิน `-stall-timeout` เซิร์ฟเวอร์ตัด request นั้น (408) แต่เก็บไบต์ที่เขียนไปแล้ว
- ตรวจพื้นที่ดิสก์ก่อนรับไฟล์ (Storage_Guard): ปฏิเสธด้วย 507 พร้อม `requiredBytes`/`availableBytes` เมื่อพื้นที่ว่างหลังหักที่จองไว้ให้ session อื่นน้อยกว่าขนาดไฟล์บวก `-min-free` ใช้กับ `POST /api/files` เดิมด้วย
- ฝั่งเบราว์เซอร์ (`web/app.js`, ตรรกะล้วนอยู่ใน `web/logic.js`) ต่อให้อัตโนมัติเมื่อ Wi-Fi หลุด: รอ 1, 2, 4, 8, 15 วินาที (15 ซ้ำ), ลองใหม่ทันทีเมื่อเบราว์เซอร์แจ้ง `online`, หยุดชั่วคราวถ้า offset ไม่เพิ่ม 10 นาที เก็บรายการที่ค้างไว้ใน `localStorage` (`lanshare.uploads.v1`) เปิดหน้าใหม่แล้วเลือกไฟล์เดิม (เทียบชื่อกับขนาด) เพื่อส่งต่อได้ และแสดงสถานะ "หยุดชั่วคราว" ของอุปกรณ์อื่นผ่าน event `transfer` สถานะ `interrupted`

**ตรวจความถูกต้องด้วย SHA-256**

- เบราว์เซอร์คำนวณ SHA-256 ใน Web Worker ขนานกับการส่ง แล้วส่งค่าไปกับ complete (หรือ `POST /api/files?sha256=...`) เซิร์ฟเวอร์คำนวณระหว่างรับไบต์โดยไม่อ่านไฟล์ซ้ำ ถ้าไม่ตรงตอบ 422 `checksum_mismatch` ลบเนื้อหาทิ้ง ไม่ publish ไฟล์
- ไฟล์มีสถานะ `integrity`: `verified` (เทียบกับค่าจากต้นทางแล้วตรง), `unverified` (ไม่ได้ส่งค่ามาเทียบ), `unknown` (ไฟล์ก่อน Phase C) UI แสดงป้าย "ตรวจแล้ว" / "ยังไม่ได้ตรวจกับต้นทาง" และหน้ารายละเอียดไฟล์แสดง checksum เต็มพร้อมปุ่มคัดลอก ปุ่มเทียบกับไฟล์ในเครื่อง
- `GET /api/files/{id}/sha256` คำนวณ checksum ให้ไฟล์ที่ยังไม่มี (ทีละไฟล์ รอคิวได้ไม่เกิน 60 วินาที) แล้วเก็บลง metadata
- ตอนส่งต่อ ถ้าเปิดการตรวจ เบราว์เซอร์แฮชช่วง `[0, offset)` ของไฟล์ที่เลือกเทียบกับ `sha256` ที่เซิร์ฟเวอร์ตอบ ถ้าไม่ตรงจะลบ session เดิมแล้วเริ่มใหม่จาก 0 แทนการต่อไฟล์ผิด

**กัน Mac หลับ** (`power.Guard` + `caffeinate`)

- ขณะมีการอัปโหลด ดาวน์โหลด หรือ zip ที่ทำงานอยู่ เซิร์ฟเวอร์รัน `/usr/bin/caffeinate -i -w <pid>` หนึ่งตัว และปล่อยหลังไม่มีงานครบ 30 วินาที session ที่ค้างระหว่างรอต่อถูกนับเป็นงานที่ถืออยู่ได้ครั้งละ 60 วินาที
- เปิดโดยค่าเริ่มต้น ปิดด้วย `-keep-awake=false` ถ้าเริ่ม `caffeinate` ไม่ได้ จะ log เตือนและสถานะเป็น `unavailable` โดยการถ่ายโอนไม่ถูกขัดจังหวะ
- `-w <pid>` ทำให้ `caffeinate` จบเองเมื่อเซิร์ฟเวอร์จบการทำงาน (ตั้งใจให้รวมกรณี `kill -9` แต่ยังไม่ได้ยืนยันบนเครื่องจริง ดูหัวข้อ "สิ่งที่ผู้ใช้ต้องตรวจเอง")

**หน้าตรวจปัญหาการเชื่อมต่อ (เฉพาะ Owner)**

- หน้า "ตรวจปัญหาการเชื่อมต่อ" แสดงผล 7 รายการ: `interface`, `firewall`, `reachability`, `wifi_band`, `disk`, `power`, `secure_context` แต่ละรายการมีสถานะ ปกติ/ควรตรวจสอบ/ผิดปกติ/ไม่ทราบ พร้อมคำแนะนำเมื่อไม่ปกติ มีปุ่ม "ตรวจใหม่" และ "คัดลอกรายงาน" (รายงานไม่มี PIN, token, Resume_Key, SSID หรือชื่อไฟล์)
- เซิร์ฟเวอร์รันคำสั่งระบบแบบอ่านอย่างเดียว (`socketfilterfw`, `networksetup`, `system_profiler`) ด้วย argv ตายตัว ไม่ผ่าน shell และ timeout ต่อคำสั่ง ผลลัพธ์ที่ parse ไม่ได้ถูกรายงานเป็น `unknown` ไม่เดา ผลถูก cache 30 วินาที
- ตรวจ `reachability` จากบันทึกที่อุปกรณ์อื่นเรียกเข้ามาล่าสุด (เก็บใน memory ไม่เกิน 256 ที่อยู่ ตัดทิ้งเมื่อเก่ากว่า 10 นาที) ไม่ได้ส่งแพ็กเก็ตออกไปทดสอบ
- แผงของ Owner แสดงสถานะกัน Mac หลับ (`active`/`idle`/`disabled`/`unavailable`) และรายการอัปโหลดที่ค้างอยู่พร้อมปุ่มยกเลิก (ไม่แสดงชื่อไฟล์และไม่มี Resume_Key)

**PWA และการแจ้งเตือนไฟล์ใหม่**

- มี `manifest.webmanifest`, ไอคอน 4 ไฟล์ (โลโก้ไฟล์กลางวงกลุ่ม สร้างด้วย `go run tools/genicons/main.go`) และ Service Worker `sw.js` ที่เก็บ cache เฉพาะไฟล์ของหน้าเว็บ (App shell) แบบ network-first ไม่แตะ `/api/*` และ `/ws` จึงไม่มี token หรือข้อมูลห้องใน cache ชื่อ cache มีเวอร์ชันที่คำนวณจากเนื้อหาไฟล์ตอนเริ่มระบบ
- แจ้งไฟล์ใหม่ในหน้า: แถบแจ้งเมื่อหน้าเปิดอยู่ และตัวเลขที่ชื่อแท็บ (`(N)`, `99+`) เมื่อหน้าถูกซ่อน รวมไฟล์ที่เข้ามาภายใน 5 วินาทีเป็น "N ไฟล์ใหม่" ไม่แจ้งไฟล์ของตัวเอง ไม่แจ้งบทบาท Uploader
- การแจ้งเตือนของระบบ (Notification API) ปิดเป็นค่าเริ่มต้น เปิดเองได้ในตั้งค่า (`lanshare.notify`) และทำงานเฉพาะขณะเปิดหน้านี้ไว้เท่านั้น ไม่มี push เมื่อปิดหน้า

**Flag ใหม่** (ตรวจค่าก่อน bind พอร์ตและก่อนสร้างโฟลเดอร์ข้อมูล ค่าที่ผิดจบด้วย error ที่ระบุชื่อ flag ค่าที่ถูกปฏิเสธ และช่วงที่ยอมรับ; `-h` พิมพ์ usage ของทุก flag)

| Flag | ค่าเริ่มต้น | ช่วงที่ยอมรับ | หน้าที่ |
|---|---|---|---|
| `-min-free` | `1GiB` | `<ตัวเลข><B\|KiB\|MiB\|GiB>` เช่น `500MiB` (หน่วยพิมพ์ตามนี้เป๊ะ ไม่มีช่องว่าง) ตั้งแต่ `0B` ถึง 9223372036854775807 ไบต์ `0B` = ไม่กันพื้นที่สำรอง | พื้นที่ว่างที่ต้องเหลือหลังรับไฟล์ |
| `-upload-ttl` | `24h` | Go duration ตั้งแต่ `1m` ขึ้นไป | อายุของ session ที่ค้างโดยไม่มีความเคลื่อนไหว |
| `-stall-timeout` | `30s` | Go duration ตั้งแต่ `5s` ขึ้นไป | ตัด request อัปโหลดที่ไม่มีข้อมูลเข้ามานานเกินนี้ |
| `-keep-awake` | `true` | `true` หรือ `false` เท่านั้น (เขียน `-keep-awake=false`) | กัน Mac หลับด้วย `caffeinate` ขณะมีการถ่ายโอน |
| `-system-preview` | `true` | `true` หรือ `false` เท่านั้น | พรีวิว HEIC, RAW, PDF, Office และข้อความด้วย `sips`/`qlmanage` ปิดด้วย `-system-preview=false` ถ้าไม่ไว้ใจไฟล์จากเครื่องอื่น |

ค่าที่ใช้จริงถูกบันทึกลง log ตอนเริ่มระบบ (ไม่มี PIN หรือ token)

**Endpoint ใหม่**

| Method และ path | ใครใช้ได้ | หน้าที่ |
|---|---|---|
| `POST /api/uploads` | อุปกรณ์ที่อัปโหลดได้ | สร้าง session |
| `GET /api/uploads/{id}` | ผู้ถือ Resume_Key | ถาม offset และ `sha256` ของไบต์ที่รับแล้ว |
| `PATCH /api/uploads/{id}?offset=N` | ผู้ถือ Resume_Key | ส่งไบต์ต่อท้าย |
| `POST /api/uploads/{id}/complete` | ผู้ถือ Resume_Key | ปิดงานและ publish ไฟล์ (ส่ง `{sha256}` เพื่อตรวจได้) |
| `DELETE /api/uploads/{id}` | ผู้ถือ Resume_Key | ยกเลิก |
| `GET /api/files/{id}/sha256` | อุปกรณ์ที่ดาวน์โหลดได้ | checksum ของไฟล์ |
| `GET /api/admin/diagnostics[?fresh=1]` | Owner | ผลตรวจการเชื่อมต่อ |
| `GET /api/admin/power` | Owner | สถานะกัน Mac หลับ |
| `GET /api/admin/uploads` | Owner | รายการอัปโหลดที่ค้างในห้อง |
| `DELETE /api/admin/uploads/{id}` | Owner | ยกเลิกอัปโหลดที่ค้าง |
| `GET /manifest.webmanifest`, `/sw.js`, `/icons/*.png` | ทุกคน (ไฟล์ static) | PWA |

Endpoint `/api/uploads...` ต้องมี token เหมือน endpoint อื่น และ Resume_Key ใช้เป็นเงื่อนไขเพิ่ม ส่วน `/api/admin/...` บทบาทอื่นนอกจาก Owner ได้ 403 โดยไม่มีการรันคำสั่งหรือยกเลิกสิ่งใด

**การตัดสินใจที่เกิดขึ้นระหว่างทำ**

- ค่าเริ่มต้นของ "ตรวจ SHA-256" ฝั่งเบราว์เซอร์คือ **เปิด** (`VERIFY_DEFAULT = true` ใน `web/app.js`) เพราะยังไม่มีผลวัดบนมือถือจริง ผู้ใช้ปิดเองได้ (`lanshare.verify`) ถ้าผลวัดภายหลังพบว่าช้ากว่า Wi-Fi มาก ให้ทบทวนค่านี้
- เซิร์ฟเวอร์เก็บ Resume_Key เป็นแฮช ไม่เก็บค่าดิบ (key มีสุ่ม 128 บิต แฮชธรรมดาจึงพอที่จะกันกรณีไฟล์ state รั่ว)
- ตอนเริ่มระบบเซิร์ฟเวอร์ไม่ลบเนื้อหาไฟล์ในห้องที่ไม่มี metadata (แค่ log เตือน)
- เทสต์ฝั่ง JavaScript ใช้ `node --test` กับ `node:assert` เท่านั้น ไม่มี npm, `package.json` หรือ `fast-check` ฟังก์ชันล้วนที่ไม่แตะ DOM อยู่ใน `web/logic.js` (และ `sha256.js`, `hash-core.js`, `sw.js`) ให้ Node โหลดได้ ไฟล์ทดสอบจะอยู่ใน `web/test/` ซึ่งไม่อยู่ใน `//go:embed` (ตอนนี้ยังไม่มีไฟล์ `*.test.js`)
- ไฟล์ที่ฝังด้วย `//go:embed` ตอนนี้: `index.html app.js style.css sha256.js hash-core.js hash-worker.js logic.js manifest.webmanifest sw.js icons`
- Resumable upload แทนที่ `startUpload` เดิมในเบราว์เซอร์ แต่ `POST /api/files` ยังใช้ได้และมีการตรวจพื้นที่ดิสก์กับ SHA-256 (`?sha256=`) ด้วย

**ข้อจำกัดที่ทราบ**

- ค่าเริ่มต้นยังเป็น HTTP ธรรมดา เปิด HTTPS ด้วย `-tls` (ใบรับรอง self-signed ในโฟลเดอร์ข้อมูล) บน HTTP เบราว์เซอร์ถือว่า `http://<IP ใน LAN>` ไม่ใช่ Secure_Context ดังนั้น Service Worker, การติดตั้งเป็นแอป และการแจ้งเตือนของระบบ ใช้ได้เฉพาะเมื่อเปิดผ่าน `localhost` หรือเมื่อใช้ HTTPS ที่เครื่องนั้นเชื่อใบรับรองแล้ว บนมือถือที่เข้าผ่าน IP ของ LAN แบบ HTTP จะเห็นข้อความ "การติดตั้งแอปและการแจ้งเตือนของระบบต้องใช้ HTTPS" ส่วนแถบแจ้งในหน้าและตัวเลขที่ชื่อแท็บยังใช้ได้
- Parser ของ `socketfilterfw` ยังมี fixture เฉพาะกรณี Firewall ปิด (`internal/usecase/diagnostics/testdata/firewall-off/`) ยังไม่เคยเห็นข้อความจริงตอน Firewall เปิดและโปรแกรมถูกอนุญาต/ถูกบล็อก/ไม่อยู่ในรายการ ตอนนี้ข้อความที่ไม่รู้จักจะถูกรายงานเป็น `unknown` (ไม่เดา) จึงไม่ผิดแต่ยังไม่ช่วยชี้ปัญหา Firewall
- ผลวัดความเร็ว SHA-256 บนมือถือจริงยังว่าง (ตารางด้านล่าง) ยังไม่ทราบว่าไฟล์ใหญ่บนมือถือจะช้าลงเท่าไรเมื่อเปิดการตรวจ
- ยังไม่ได้ทดสอบบนอุปกรณ์จริงทั้งการต่ออัปโหลดหลัง Wi-Fi หลุด การพับหน้าจอ iOS Safari และการใช้หน่วยความจำของเซิร์ฟเวอร์กับไฟล์ใหญ่
- เหตุการณ์ความคืบหน้า (`transfer`) และเหตุการณ์ไฟล์/แชท ของ Hub กรองตามสิทธิ์แล้ว: อุปกรณ์ที่รออนุมัติได้เฉพาะ `devices`, บทบาท Uploader ไม่เห็นไฟล์ แชท และความคืบหน้าของคนอื่น
- ถ้ารันด้วย `go run` ไบนารีชั่วคราวเปลี่ยนทุกครั้ง macOS Firewall อาจถามอนุญาตใหม่ และผลตรวจ `firewall` ตอนพัฒนาอาจต่างจากไบนารีที่ติดตั้งจริง

**เทสต์ที่ยังไม่ได้เขียน**

งานเทสต์ที่ spec ระบุเป็นตัวเลือก (`*`) ยังไม่ได้เขียน ได้แก่ property test ทั้งหมดของ `reliable-transfers` (เช่น resume round trip, invariant ของ offset, การแยกห้อง, Storage_Guard, size round trip), เทสต์ SHA-256/`hash-worker`/`logic`/Service Worker ด้วย `node --test`, เทสต์ของ `PartialStore`, `sessionstore`, `power.Guard`, `diagnostics` และ parser, เทสต์ static/PWA ฝั่ง Go, และเทสต์ integration ของไบนารี (`-tags integration`) ยังไม่ได้เพิ่ม dependency `pgregory.net/rapid` ตอนนี้จึงมีเฉพาะเทสต์เดิมก่อน Phase C ที่ต้องผ่านต่อ (`go test ./...`) ไม่มีเทสต์อัตโนมัติฝั่งเบราว์เซอร์

**สิ่งที่ผู้ใช้ต้องตรวจเอง (บนเครื่องจริง)**

1. **วัดความเร็ว SHA-256 บน iPhone และ Android จริง** ตามขั้นตอนในหัวข้อถัดไป แล้วกรอกตาราง
2. **เก็บ fixture ของ Firewall ตอนเปิด** บน Mac: เปิด macOS Firewall เองในการตั้งค่าระบบ แล้วรัน `internal/usecase/diagnostics/testdata/capture.sh` (สคริปต์อ่านอย่างเดียว ไม่เปลี่ยนค่า Firewall) ซ้ำสำหรับกรณีโปรแกรมถูกอนุญาต ถูกบล็อก และไม่อยู่ในรายการ ตามขั้นตอนใน `testdata/README.md` แล้วเพิ่มเทสต์ของ parser
3. **ทดสอบต่ออัปโหลดบนอุปกรณ์จริง:** ส่งไฟล์ใหญ่แล้วปิด Wi-Fi/เปิดใหม่ระหว่างส่ง, พับหน้าจอ iOS Safari ระหว่างส่ง, ปิดแท็บแล้วเปิดหน้าใหม่เลือกไฟล์เดิมเพื่อส่งต่อ, รีสตาร์ตเซิร์ฟเวอร์ระหว่างส่ง, ส่งไฟล์เกิน 1 GB แล้วดูว่า RSS ของเซิร์ฟเวอร์ไม่โตตามขนาดไฟล์
4. **ทดสอบกัน Mac หลับ:** ขณะส่งไฟล์ ตรวจ `pmset -g assertions` ว่ามี assertion ของ `caffeinate` แล้วสั่ง `kill -9` ที่เซิร์ฟเวอร์ ตรวจว่า `caffeinate` ถูกปล่อยภายใน 5 วินาที
5. **ทดสอบ Web Worker, Service Worker และ Notification บนเบราว์เซอร์จริง** (Service Worker กับ Notification ต้องเปิดผ่าน `http://localhost:8080` บน Mac เพราะ LAN ยังเป็น HTTP)

### ผลวัด SHA-256 บนมือถือ

SHA-256 ฝั่งเบราว์เซอร์เป็น JavaScript ล้วนใน Web Worker (WebAssembly ใช้ไม่ได้เพราะ CSP ต้องไม่ผ่อน) จึงต้องวัดความเร็วบนมือถือจริงเพื่อกำหนดค่าเริ่มต้นของการตรวจ SHA-256 ผลวัดของ Node ไม่ใช่ตัวแทนของมือถือ

วิธีวัด:

1. บน Mac รัน `go run web/test/bench/main.go` (ค่าเริ่มต้นพอร์ต 8090) แล้วอ่านคำเตือนที่พิมพ์ออกมา เซิร์ฟเวอร์นี้ไม่มีการยืนยันตัวตนและเสิร์ฟไฟล์ static ของ `web/` ให้ทุกคนใน LAN ใช้ชั่วคราวเท่านั้น
2. เปิด URL ที่พิมพ์ออกมาบนมือถือที่อยู่ใน Wi-Fi เดียวกัน กด "วัดทั้งสอง" ปล่อยหน้าไว้จนเสร็จ
3. กด "คัดลอกผล" แล้วนำ MB/s ของ 100 MB และ 1 GB มากรอกในตารางด้านล่าง
4. กด Ctrl+C บน Mac เพื่อปิดเซิร์ฟเวอร์วัดทันทีเมื่อเสร็จ

ตัวเลขเปรียบเทียบ: ความเร็วอัปโหลดจริงของ Wi-Fi ที่ใช้ (ดูจากความเร็วที่ UI แสดงตอนส่งไฟล์) ถ้า SHA-256 ช้ากว่านี้มาก ให้ทบทวนค่าเริ่มต้นของ "ตรวจ SHA-256" (ตอนนี้เปิดไว้ เพราะ Phase C สร้างเสร็จก่อนมีผลวัด) เช่นตั้งเป็นปิดสำหรับไฟล์ใหญ่ โดยแก้ `VERIFY_DEFAULT` ใน `web/app.js`

### รายละเอียด Phase H ที่ทำจริง

Wi-Fi และสาย USB เข้าเซิร์ฟเวอร์ตัวเดียวกันที่พอร์ตเดียวกัน กรอก PIN เดียวกัน ถ้ามีเซิร์ฟเวอร์ทำงานอยู่แล้ว (เช่น แอป menu bar) `scripts/run-local.sh` จะไม่เปิดตัวใหม่ แค่คง `adb reverse` เข้าเซิร์ฟเวอร์นั้น

**การเชื่อมต่อสาย**

- ตรวจโทรศัพท์ที่เสียบ USB จาก `ioreg` และอินเทอร์เฟซ `NetUSB` จาก `networksetup` สถานะ `idle` / `plugged` / `ready`
- Android: ใช้ `adb reverse tcp:<port> tcp:<port>` แล้วมือถือเปิด `http://127.0.0.1:<port>/?r=<ห้อง>` ได้โดยไม่ต้องมีเน็ต ปุ่ม "เปิดไฟล์" ส่ง `am start` ด้วย VIEW intent
- iPhone/iPad: ใช้เครือข่าย USB (Personal Hotspot) หรือ URL/QR ในแผงเชิญ ลองเปิด Safari ด้วย `xcrun devicectl` ถ้าเปิดไม่ได้ Owner สแกน QR หรือเปิดลิงก์บนเครื่องเอง
- รายการอุปกรณ์แยกกลุ่ม Wi-Fi กับสาย USB เครื่องที่เสียบสายแต่ยังไม่เข้าห้องมีป้าย "เสียบสาย"

**เรียกดูไฟล์บนเครื่อง (เฉพาะ Owner)** แท็บ "ไฟล์บนเครื่อง" ต้นแบบ UI: [`mock/ui-mock-v3.html`](../mock/ui-mock-v3.html)

- แสดงเฉพาะเครื่องที่เสียบสายตอนนี้ ถ้ามี Android มากกว่าหนึ่งเครื่องให้เลือกเครื่องก่อนเข้าโฟลเดอร์
- มุมมองรายการ / ไอคอน / แกลเลอรี ไม่มี checkbox กดรายการเพื่อเลือก ดับเบิลคลิกเข้าโฟลเดอร์ กดไฟล์แล้วเปิดพรีวิว (รูป / ข้อความ / ข้อมูลดิบ อ่านต้นไฟล์ไม่เกิน 16 KiB) รายการต่อโฟลเดอร์ใน UI ไม่เกิน 400 รายการ
- เลือกหลายรายการแบบ Finder: Shift เลือกช่วง, ⌘ สลับเลือกรายการนั้น (กดซ้ำแล้วออก), ⌘A เลือกทั้งหมด ทั้งไฟล์บนเครื่องและไฟล์ในห้อง หลังใช้ ⌘ แล้วกด Shift จะเก็บชุดที่เลือกไว้ แล้วเพิ่มช่วงจากจุดยึดถึงรายการใหม่
- บันทึกลง Mac: ไฟล์เดียวดาวน์โหลดตรง โฟลเดอร์หรือหลายรายการเป็น zip ชื่อตามโฟลเดอร์ (สูงสุด 5000 ไฟล์ ลึกไม่เกิน 24 ชั้น การเดิน zip ไม่ตัดที่ 400 รายการของ UI) โฟลเดอร์ว่างหรืออ่านไม่ได้มีข้อความบอก ไม่สร้าง zip ว่างเงียบ
- บันทึกโฟลเดอร์ Android ดึงทั้งโฟลเดอร์ครั้งเดียวด้วย `adb pull` ไม่ดึงทีละไฟล์ เบราว์เซอร์ที่รองรับ `showSaveFilePicker` ให้เลือกที่เซฟก่อน มิฉะนั้นเริ่มดาวน์โหลดทันทีหลังกด (ไม่รอตรวจแผน) เซิร์ฟเวอร์ส่ง header ของ zip ก่อนเริ่มดึงจากมือถือ
- ดึงเข้าห้องแชร์ (import) จากแถบเลือกหลายรายการหรือจากพรีวิว แล้วสลับไปแท็บไฟล์ในห้อง
- Android ต้องเปิด USB debugging แล้วกด Trust โฟลเดอร์ลัด: แอป, ดาวน์โหลด, รูปภาพ, กล้อง, วิดีโอ, เอกสาร, เพลง, ที่เก็บข้อมูล (`/sdcard`)
- Android ทำได้เพิ่ม: ลบไฟล์/โฟลเดอร์ (ลบโฟลเดอร์ลัดไม่ได้), สร้างโฟลเดอร์ด้วยไดอะล็อกในหน้าแล้วเปิดโฟลเดอร์นั้นให้วาง, คัดลอกและตัดแล้วกลับไปเปิดหน้าที่จะวาง (คีย์ลัด ⌘C / ⌘X / ⌘V) มี overlay และข้อความค้างระหว่างทำงาน
- ไฟล์คัดลอกหรือตัดวางบนเครื่องเดียวกันได้ วางลงโฟลเดอร์เดิมได้สำเนาชื่อ `ชื่อ (2).ext` การตัดในโฟลเดอร์เดิมไม่ลบต้นฉบับ แอป (APK) วางได้เฉพาะเครื่องอื่น ไม่เกิน 8 แอปต่อครั้ง เลือกแอปกับไฟล์พร้อมกันไม่ได้ การวางแอปใช้ `adb install`

## 12. สรุปฟีเจอร์ที่มีอยู่จริง

แคตตาล็อกสิ่งที่โปรแกรมทำได้วันนี้ (23 ตุลาคม 2026) เรียงตามงานของผู้ใช้ ไม่ใช่แผนเฟส รายละเอียดเทคนิคของแต่ละเฟสอยู่หัวข้อ 11

### 12.1 เข้าห้อง

- ติดตั้งโฮสต์จาก `dist/<เวอร์ชัน>/` (Mac / Android / Windows) อุปกรณ์อื่นใช้เบราว์เซอร์ ไม่ต้องลงแอปลูกข่าย iOS ยัง build จาก Xcode
- เปิด `http://localhost:8080` บน Mac แล้วเข้าระบบเป็น Owner อัตโนมัติ (`POST /api/owner/session`) ไม่ต้องใส่ PIN
- เข้าด้วย URL หรือ QR แล้วกรอก PIN 6 หลัก ต่อห้อง พร้อมใส่ชื่ออุปกรณ์
- กรอก PIN ผิดเกินกำหนดแล้วถูกล็อกชั่วคราว (ค่าเริ่มต้น 5 ครั้ง / 5 นาที)
- ลิงก์แขก: เข้าได้โดยไม่ใส่ PIN อัปโหลดอย่างเดียว อายุ 1 ชั่วโมง
- Owner เปิด "อนุมัติอุปกรณ์ใหม่ก่อนเข้าใช้ห้อง" ได้ อุปกรณ์ที่รอเห็นหน้าค้างจนกว่าจะถูกอนุมัติ
- Wi-Fi และสาย USB เข้าเซิร์ฟเวอร์ตัวเดียวกัน PIN เดียวกัน

### 12.2 ห้อง บทบาท และสิทธิ์

| บทบาท | อัปโหลด | ดาวน์โหลด | ข้อความ / คลิปบอร์ด | จัดการห้อง |
|---|---|---|---|---|
| Owner | ได้ | ได้ | ได้ | ได้ |
| Member | ได้ | ได้ | ได้ | ไม่ได้ |
| Viewer | ไม่ได้ | ได้ | อ่านอย่างเดียว | ไม่ได้ |
| Uploader (แขก) | ได้ | ไม่ได้ | ไม่ได้ | ไม่ได้ |

- สร้างหลายห้อง สลับห้อง เปลี่ยนชื่อ ลบห้อง (ลบห้องหลัก `main` ไม่ได้ แม้มีห้องอื่น)
- ห้องใหม่คัดลอก `RequireApproval` จากห้องปัจจุบันของ Owner
- สแกน QR หรือเปิด `?r=` ของอีกห้อง ต้องกรอก PIN ของห้องนั้น แม้เบราว์เซอร์ยังมี cookie ห้องเก่า
- แต่ละห้องมี PIN, โฟลเดอร์ไฟล์, รายชื่ออุปกรณ์ของตัวเอง ห้องหนึ่งมองไม่เห็นไฟล์ของอีกห้อง

- Owner อนุมัติ ปฏิเสธ ถอด เปลี่ยนบทบาท และตั้งชื่ออุปกรณ์ได้
- อุปกรณ์ออนไลน์แบบเรียลไทม์ แยกกลุ่ม Wi-Fi กับสาย USB

### 12.3 ส่งและรับไฟล์ในห้อง

ต้นแบบ: [`mock/ui-mock-v3.html`](../mock/ui-mock-v3.html) เมนูถ่ายโอนสำหรับส่งไฟล์ และแท็บไฟล์ในห้องสำหรับดู/ดาวน์โหลด

- อัปโหลดอยู่ในเมนู **ถ่ายโอน** (Owner, Member, Uploader) ดาวน์โหลดอยู่ในเมนู **ไฟล์** ส่งสองทิศทางแบบ stream (ไฟล์หลาย GB ไม่โหลดทั้งก้อนเข้า RAM) มี progress และความเร็ว
- ลากวางไฟล์ เลือกหลายไฟล์ เลือกโฟลเดอร์บนคอมพิวเตอร์ (มือถือเลือกโฟลเดอร์ไม่ได้)
- วางภาพจากคลิปบอร์ดด้วย ⌘V / Ctrl+V แล้วส่งเป็นสกรีนช็อต
- ชื่อซ้ำ: ถามทุกครั้ง, เก็บทั้งสองไฟล์, เขียนทับ, หรือข้าม และทำแบบนี้กับไฟล์ที่เหลือได้ (เขียนทับได้เฉพาะไฟล์ที่ตัวเองส่งหรือ Owner)
- ดาวน์โหลดหลายไฟล์เป็น zip สูงสุด 500 ไฟล์ ไม่บีบอัด รักษาโครงสร้างโฟลเดอร์
- เลือกแบบ Finder ไม่มี checkbox: กดเลือก, Shift ช่วง, ⌘ สลับ, ⌘A ทั้งหมด แถบเลือกเป็น zip / ลบ / ล้าง
- ลบไฟล์ได้ตามสิทธิ์ (Owner ลบได้ทั้งหมด ผู้ส่งลบไฟล์ของตัวเอง)
- ค้นหาชื่อไฟล์หรืออุปกรณ์ เรียงล่าสุด / ตามอุปกรณ์ / ตามวันที่
- ย่อรูปใหญ่ก่อนส่ง (ยาวสุด 1920 พิกเซล) เปิด-ปิดในตั้งค่า
- HEIC/HEIF ที่อัปโหลดบน Mac แปลงเป็น JPG ด้วย `sips` หลังส่งเสร็จ
- สตรีมวิดีโอ เพลง รูป PDF ในหน้าเว็บด้วย HTTP Range (`?view=1`) ไม่ต้องดาวน์โหลดทั้งไฟล์
- พรีวิวข้อความโค้ดพร้อม syntax highlight, thumbnail รูป, พรีวิวเอกสารด้วย Quick Look บน Mac (ปิดได้ด้วย `-system-preview=false`)
- หน้ารายละเอียดไฟล์แสดง SHA-256 พร้อมปุ่มคัดลอก และเทียบกับไฟล์ในเครื่อง
- Web Share Target บน Android (PWA): แชร์ไฟล์จากแอปอื่นเข้าห้อง

### 12.4 ความเสถียรและความถูกต้อง

- Resumable upload: ส่งเป็นก้อน ต่อจากจุดที่ค้างเมื่อ Wi-Fi หลุด รีสตาร์ตเซิร์ฟเวอร์ หรือปิดแท็บแล้วเลือกไฟล์เดิม มีสถานะกำลังเชื่อมต่อใหม่ / หยุดชั่วคราวพร้อมปุ่ม "ต่อ" / ยกเลิก
- ตรวจ SHA-256 ทั้งเบราว์เซอร์และเซิร์ฟเวอร์ ค่าเริ่มต้นเปิด ปิดได้ในตั้งค่า ป้าย "ตรวจแล้ว" / "ยังไม่ได้ตรวจกับต้นทาง"
- กันดิสก์เต็มก่อนรับไฟล์ (ค่าเริ่มต้นเหลืออย่างน้อย 1 GiB)
- กัน Mac หลับระหว่างมีการถ่ายโอนด้วย `caffeinate` (ปิดด้วย `-keep-awake=false`)
- หน้าตรวจปัญหาการเชื่อมต่อสำหรับ Owner (เมนูแยก): การ์ดเครือข่าย, Firewall, เครื่องที่เคยเข้ามา, ย่าน Wi-Fi, ดิสก์, กันหลับ, Secure_Context ปุ่มตรวจใหม่และคัดลอกรายงาน
- Owner เห็นรายการอัปโหลดที่ค้างในห้องและยกเลิกได้ (ไม่โชว์ชื่อไฟล์หรือ Resume_Key)
- PWA: ติดตั้งแอปและแจ้งเตือนไฟล์ใหม่ (ต้อง HTTPS หรือ `localhost`) มีแถบแจ้งในหน้าและตัวเลขที่ชื่อแท็บแม้บน HTTP

### 12.5 ข้อความและคลิปบอร์ดร่วม

- คลิปบอร์ดร่วม: แชร์ข้อความหรือลิงก์ได้ถึง 20,000 ตัวอักษร คัดลอกลงเครื่องนี้หรือล้างได้
- ข้อความในห้อง สูงสุด 4,000 ตัวอักษรต่อข้อความ เก็บล่าสุด 200 ข้อความต่อห้องในหน่วยความจำ (หายเมื่อรีสตาร์ตเซิร์ฟเวอร์)
- Uploader ใช้ข้อความและคลิปบอร์ดไม่ได้ Viewer อ่านได้อย่างเดียว

- เสียบมือถือแล้วเข้าห้องโดยไม่ต้องมีเน็ต (Android ผ่าน ADB reverse, iPhone ผ่าน USB network / Personal Hotspot)
- ปุ่มเปิดหน้าไฟล์บนมือถือจากแดชบอร์ด มี QR แยกสำหรับเส้นทางสาย
- แถบด้านข้างแสดงเฉพาะเครื่องที่เสียบสายตอนนี้ ถ้ามี Android สองเครื่องให้เลือกเครื่องก่อน
- แท็บ "ไฟล์บนเครื่อง": มุมมองรายการ / ไอคอน / แกลเลอรี ไม่มี checkbox กดเพื่อเลือก ดับเบิลคลิกเข้าโฟลเดอร์ กดไฟล์แล้วเปิดพรีวิว (พรีวิว / ข้อความ / ข้อมูลดิบ)
- เพดาน 400 รายการต่อโฟลเดอร์: ถ้าโฟลเดอร์บนมือถือมีไฟล์มากกว่านี้ หน้าเว็บแสดงแค่ 400 รายการแรก (กันหน้าค้าง) ข้อความบอกว่าเป็นรายการแรก การบันทึกทั้งโฟลเดอร์เป็น zip ยังเดินต่อในโฟลเดอร์ย่อยได้ถึง 5000 ไฟล์
- เลือกหลายรายการแบบ Finder: Shift ช่วง, ⌘ สลับ (กดซ้ำแล้วออก), ⌘A ทั้งหมด หลัง ⌘ แล้วกด Shift จะเก็บชุดเดิมแล้วเพิ่มช่วงใหม่
- แถบเลือก: คัดลอก ⌘C, ตัด ⌘X, ดึงเข้าห้อง, บันทึกลงเครื่อง, ลบ แถบคลิปบอร์ด: โฟลเดอร์ใหม่, วาง ⌘V, ล้าง มี overlay ระหว่างทำงาน
- บันทึกลง Mac: ไฟล์เดียวดาวน์โหลดตรง โฟลเดอร์หรือหลายรายการเป็น zip ชื่อโฟลเดอร์ สูงสุด 5000 ไฟล์ ดึงทั้งโฟลเดอร์ครั้งเดียว โฟลเดอร์ว่างหรืออ่านไม่ได้มีข้อความบอก
- ดึงหลายรายการเข้าห้องแล้วสลับไปแท็บไฟล์ในห้อง
- Android (USB debugging + Trust): โฟลเดอร์ลัด แอป/ดาวน์โหลด/รูป/กล้อง/วิดีโอ/เอกสาร/เพลง/ที่เก็บข้อมูล, ลบ, สร้างโฟลเดอร์แล้วเปิดให้วาง, คัดลอก/ตัด/วางบนเครื่องเดียวกันหรือข้ามสาย (แอปวางได้เฉพาะเครื่องอื่น รวมติดตั้ง APK)
- วางไฟล์ลงโฟลเดอร์เดิมได้สำเนา `ชื่อ (2).ext` การตัดในโฟลเดอร์เดิมไม่ลบต้นฉบับ
- iPhone: ดูได้เฉพาะแอปจาก Xcode ไม่ลบ/ไม่สร้างโฟลเดอร์ผ่านสาย แอป Files ของระบบเรียกดูผ่าน USB ไม่ได้

### 12.7 หน้าตาและภาษา

- แดชบอร์ดบน Mac และมือถือใช้เมนูชุดเดียวกัน: **เชิญ** (เฉพาะ Owner — QR, PIN, เครือข่าย, โควตา, ลิงก์แขก), **ถ่ายโอน** (Owner, Member, Uploader — ซ่อนจาก Viewer), ไฟล์, ข้อความ / คลิปบอร์ด, ตรวจปัญหาการเชื่อมต่อ (Owner), ตั้งค่า, เกี่ยวกับระบบ
- ธีมตามระบบ / มืด / สว่าง
- ภาษาไทยเป็นค่าเริ่มต้น สลับได้ 16 ภาษาในตั้งค่า: ไทย, English, 中文, Español, हिन्दी, العربية, Français, Português, Русский, 日本語, Deutsch, 한국어, বাংলা, Bahasa Indonesia, ລາວ, ខ្មែរ (อาหรับใช้ RTL)
- ตั้งค่า: ย่อรูปก่อนส่ง, ตรวจ SHA-256, แจ้งเตือนของระบบ (ติดตั้ง PWA ได้เฉพาะ Secure_Context)
- เมนูเกี่ยวกับระบบ: โลโก้ไฟล์กลางวงกลุ่ม, ชื่อโปรแกรม, เวอร์ชัน `0.2.1`, ผู้พัฒนา `nooartskyline`, และคำอธิบายสั้นว่าโฮสต์อยู่บน Mac

### 12.8 เครื่องมือบน Mac

- แอป menu bar (`desktop/LanShareMenu`): ซ่อนจาก Dock แสดง PIN ห้อง เครือข่าย จำนวนอุปกรณ์ และที่รออนุมัติ เปิดแดชบอร์ดและเปิดเมื่อเข้าสู่ระบบได้
- CLI: `go run ./cmd/share send <ไฟล์>` อัปโหลดเข้าห้องปัจจุบันในฐานะ Owner ผ่าน localhost
- Finder Quick Action: คลิกขวาไฟล์ → ส่งไป Share Group
- HTTP API สำหรับ Shortcuts เรียกได้เฉพาะ `127.0.0.1` / `localhost` ไม่ต้องใส่ PIN: ข้อมูลห้อง, QR, รายการไฟล์, อัปโหลด
- HTTPS ด้วย `-tls` (ใบรับรอง self-signed ในโฟลเดอร์ข้อมูล)
- `-system-preview` (ค่าเริ่มต้นเปิด) ใช้ `sips`/`qlmanage` วาดพรีวิว HEIC, RAW, PDF, Office และข้อความ ปิดได้ถ้าไม่ไว้ใจไฟล์จากเครื่องอื่น

### 12.9 สิ่งที่ยังไม่อยู่ในโปรแกรม

ยังนอกขอบเขตตามหัวข้อ 5 ได้แก่ ส่งตรงมือถือถึงมือถือด้วย WebRTC, เข้ารหัสไฟล์แบบ end-to-end, แอปเนทีฟฝั่งลูกข่าย, ใช้งานข้ามอินเทอร์เน็ต, บัญชีผู้ใช้/คลาวด์, และโฮสต์บน Linux

โฮสต์ Windows / Android / iOS อยู่ใน Phase I โค้ดอยู่ใน `desktop/windows`, `mobile/android`, `mobile/ios` Android และ iOS เทสเส้นหลักบนเครื่องจริงแล้ว Windows ยังไม่มีเครื่องเทส ต้นแบบผิวมีใน [`mock/ui-mock-hosts.html`](../mock/ui-mock-hosts.html) หน้าตาที่ผู้ใช้เห็นยึดแดชบอร์ด Mac รวมเมนูเชิญ (Owner) และถ่ายโอน (โฮสต์และผู้ใช้ที่อัปโหลดได้) ไม่สร้างชุดจอใหม่ สแตก: แกน Go + `web/` เปลือก Windows เป็น Go ทั้งก้อน, Android เป็น Kotlin ห่อ Go, iOS เป็น Swift ห่อ Go (ดูหัวข้อ 4)

ข้อจำกัดที่ยังมีผล: router ต้องไม่เปิด AP Isolation, iOS Safari เลือกโฟลเดอร์ปลายทางเองไม่ได้, ฝั่งมือถือต้องกดดาวน์โหลดเอง, PWA/การแจ้งเตือนของระบบต้องใช้ Secure_Context, เรียกดูไฟล์ในแอป Files ของ iPhone ผ่าน USB ยังไม่ได้, Android ยังไม่เทส OTG จริงกับไฟล์ใหญ่หลาย GB, Windows ยังไม่มีเครื่องเทส (ดูหัวข้อ 4 และ 11)

## 13. ภาพรวมระบบ

Share Group ไม่ใช่เว็บบนคลาวด์ และไม่ใช่แอปลูกข่าย ระบบที่รันวันนี้มีสองชั้นบน Mac ของเจ้าของเครื่อง โฮสต์ Windows / Android / iOS อยู่ Phase I โค้ดครบ Android และ iOS เทสเส้นหลักบนเครื่องจริงแล้ว Windows ยังไม่มีเครื่องเทส แกนยังเป็น Go + `web/` เปลือกเนทีฟบาง ๆ ตามหัวข้อ 4

| ชั้น | คืออะไร | อยู่ที่ไหน |
|---|---|---|
| หลังบ้าน | โปรแกรม Go ตัวเดียว เปิด HTTP + WebSocket ที่พอร์ต `8080` | `cmd/lanshare` ประกอบ `internal/` |
| หน้าเว็บ | HTML/CSS/JS ที่ผู้ใช้เห็นในเบราว์เซอร์ | `web/` ฝังในไบนารีด้วย `embed` |
| เปลือกโฮสต์ | เปิด-ปิดเซิร์ฟเวอร์และงาน OS ไม่ใส่กฎห้อง | Mac: `desktop/LanShareMenu` (Swift) · Windows: `desktop/windows` (Go, Phase I) · Android: `mobile/android` (Kotlin, Phase I) · iOS: `mobile/ios` (Swift, Phase I) |
| เครื่องอื่น | เบราว์เซอร์อย่างเดียว ไม่มีเซิร์ฟเวอร์ของตัวเอง | เปิด URL หรือสแกน QR แล้วกรอก PIN |
| ต้นแบบ UI | ไฟล์ HTML คลิกดูหน้าตา ไม่ต่อหลังบ้าน | `mock/` ดูหัวข้อ 15 |

```
อุปกรณ์ (เบราว์เซอร์)
    │  HTTP / WebSocket ในวง LAN หรือสาย USB
    ▼
เครื่องโฮสต์ (วันนี้คือ Mac, Phase I เพิ่ม Windows / Android / iOS)
    ├─ เปลือกเนทีฟ (เปิด-ปิด, แจ้งเตือน, Hotspot / OTG ถ้ามี)
    ├─ โปรแกรม lanshare (หลังบ้าน Go: ห้อง, PIN, สิทธิ์, ไฟล์)
    └─ เสิร์ฟหน้าเว็บจาก web/
```

เปิด `http://localhost:8080` บน Mac แล้วเป็น Owner อัตโนมัติ (`POST /api/owner/session`) ไม่ต้องใส่ PIN เครื่องอื่นใช้ PIN หรือลิงก์แขก

ข้อมูลอยู่บนดิสก์ของ Mac ไม่มีบัญชีผู้ใช้และไม่ซิงค์ขึ้นอินเทอร์เน็ต

| โฟลเดอร์ข้อมูล | เมื่อไหร่ |
|---|---|
| `~/LANShare` | `go run ./cmd/lanshare` หรือไบนารีที่ติดตั้ง |
| `./tmp/local` | `sh scripts/run-local.sh` (พัฒนาในโปรเจกต์) |
| `state.json` | ห้อง ไฟล์ อุปกรณ์ที่จำไว้ |
| `sessions/` และ `partial/` | อัปโหลดที่ยังไม่เสร็จ |
| โฟลเดอร์ไฟล์ต่อห้อง | เนื้อหาที่แชร์ |

ส่วนเสริมบน Mac ที่ไม่ใช่หน้าเว็บ: แอป menu bar (`desktop/LanShareMenu`), CLI `cmd/share`, Finder Quick Action, Shortcuts เรียก `127.0.0.1` เท่านั้น

## 14. ข้อมูลสำหรับนักพัฒนา

แหล่งอ้างอิงอื่น: กฎชั้นโค้ดใน `.kiro/steering/structure.md` สแตกใน `.kiro/steering/tech.md` ผลิตภัณฑ์ใน `.kiro/steering/product.md`

### สิ่งที่ต้องมี

- macOS (เครื่องที่ใช้ build วันนี้; ไฟล์ติดตั้งโฮสต์ Windows / Android อยู่ที่ `dist/`)
- Go 1.27 ขึ้นไป (module `lanshare`)
- ถ้าจะเทสสาย Android: `adb` จาก Android platform-tools
- ถ้าจะแพ็ก Android: Android SDK + NDK และ `gomobile`
- หน้าเว็บไม่มี npm / ไม่มีขั้นตอน build ของ frontend

### รันระหว่างพัฒนา

```bash
sh scripts/run-local.sh          # พอร์ต 8080, ข้อมูลที่ ./tmp/local, ต่อ ADB reverse ถ้ามี
go run ./cmd/lanshare            # ข้อมูลที่ ~/LANShare
go run ./cmd/lanshare -h         # flag ทั้งหมด
```

ถ้ามีเซิร์ฟเวอร์เปิดอยู่แล้วที่พอร์ตเดียวกัน สคริปต์จะไม่เปิดตัวใหม่ แค่เชื่อมสาย USB เข้าตัวนั้น หยุดด้วย Ctrl+C

หน้าจริงอยู่ที่ `http://localhost:8080` ต้นแบบอยู่ที่ `mock/ui-mock-v3.html` (เปิดไฟล์ตรง ๆ ไม่ต้องมีเซิร์ฟเวอร์)

### ทดสอบ

```bash
go test ./...
go test ./internal/usecase/...
go test -race ./...
node --test web/test/
gofmt -l .
```

แก้ `web/` แล้วรีเฟรชเบราว์เซอร์พอ ถ้าเพิ่มไฟล์ใหม่ใน `web/` ต้องใส่ใน `//go:embed` ของ `web/embed.go` ห้ามฝัง `web/test/`

### ไฟล์ติดตั้ง

เวอร์ชันปัจจุบันอ่านจากไฟล์ `VERSION` ที่รากโปรเจกต์ (ตอนนี้ `0.2.1`) ไฟล์ติดตั้งอยู่ที่ `dist/<เวอร์ชัน>/` รุ่นเก่าเช่น `dist/0.2.0/` และ `dist/0.1.0/` ไม่ถูกลบเวลาแพ็กรุ่นใหม่ ลิงก์โหลดอยู่ที่ [GitHub Releases](https://github.com/NooartSkyline/share-group/releases) และหน้า [`dist/index.html`](../dist/index.html)

```bash
sh scripts/package-hosts.sh          # Mac .dmg, Android .apk, Windows .zip → dist/<เวอร์ชัน>/
```

รายการลิงก์และวิธีติดตั้งอยู่ที่ [`README.md`](../README.md) หัวข้อไฟล์ติดตั้ง iOS ยังไม่มี IPA ใน `dist/` ให้ Run จาก Xcode

### โครงสร้างที่ใช้อยู่

```
cmd/lanshare/           CLI เรียก internal/app
internal/app/           composition root ที่ใช้ร่วมกับโฮสต์มือถือ
mobilehost/             Start/Stop/URL สำหรับ gomobile
mobile/android/         เปลือก Kotlin ห่อ Go (WebView, FGS, bind.sh)
cmd/share/              CLI อัปโหลดผ่าน localhost
internal/domain/        entity และกฎ ห้ามรู้จัก HTTP/SQL/ดิสก์
internal/usecase/       กรณีใช้งาน + port
internal/adapter/       HTTP, WebSocket, ดิสก์, ADB, QR, diagnostics
internal/infra/         config, clock, TLS
web/                    หน้าจริง (index.html, app.js, style.css, logic.js)
desktop/LanShareMenu/   เปลือก menu bar บน Mac (Swift)
desktop/windows/        เปลือกถาดระบบ Windows (ถาด + คลิกขวา Explorer)
mobile/ios/             เปลือก Swift ห่อ Go (WKWebView, bind.sh, ใช้ได้ตอนแอปเปิดอยู่)
mock/                   ต้นแบบ UI (หัวข้อ 15)
docs/project-scope.md   เอกสารขอบเขตหลัก (ภาษาไทย)
scripts/run-local.sh    รันพัฒนา + USB
scripts/package-hosts.sh แพ็กไฟล์ติดตั้งโฮสต์เข้า dist/<เวอร์ชัน>/
dist/<เวอร์ชัน>/        ไฟล์ติดตั้งที่แจก (รุ่นเก่าเก็บแยกโฟลเดอร์)
VERSION                 เลขเวอร์ชันปัจจุบัน
```

สถานะช่วงพัฒนาเก็บ JSON (`jsonstore`) ยังไม่ย้ายไป SQLite ตามแผนหัวข้อ 3.2

### กฎที่ห้ามทำพัง

- ไฟล์ใหญ่ต้อง stream ห้ามโหลดทั้งก้อนเข้า RAM
- ทุกการเข้าถึงไฟล์หรือข้อความต้องมี `RoomID` และตรวจบทบาท
- ห้าม log หรือแสดง Resume_Key, PIN, token (ยกเว้น PIN ในแบนเนอร์ตอนเริ่มระบบ)
- commit message เป็นภาษาไทย คำศัพท์เทคนิคคงภาษาอังกฤษตามในโค้ด
- UI ที่ผู้ใช้เห็นค่าเริ่มต้นเป็นภาษาไทย

- กด **ถ่ายโอน** เพื่อลากไฟล์ กด **ไฟล์** เพื่อดูไฟล์ในห้อง / ไฟล์บนเครื่อง
- กด **ออกจากห้อง** เพื่อดูจอ PIN ของมือถือ PIN ทดลอง `482916`
- กด URL ลิงก์แขกในเมนูเชิญ เพื่อดูจอเข้าโดยไม่มีช่อง PIN
- กรอก PIN เมื่อเปิดอนุมัติอุปกรณ์ไว้ จะเข้าจอรออนุมัติ
- ในตั้งค่ามีตัวสลับบทบาท Owner / Member / Viewer / Uploader เพื่อดูสิทธิ์
- แท็บไฟล์บนเครื่อง: Android มีโฟลเดอร์ลัด, iPhone ดูได้เฉพาะแอป Xcode, โฟลเดอร์วอลเปเปอร์โชว์ข้อความเพดาน 400

### สิ่งที่ v3 ครอบคลุมจากโค้ด

เข้าห้อง, รออนุมัติ, การ์ดเชิญ (QR Wi-Fi, PIN, เครือข่าย, โควตา, TTL, แขก), ถ่ายโอนแบบหยุด/ต่อ/ยกเลิก, ชื่อซ้ำ, ไฟล์ในห้อง, ไฟล์บนสาย USB, ข้อความและคลิปบอร์ด, ตั้งค่า, ตรวจปัญหา 7 ข้อ, ยกเลิกอัปโหลดที่ค้าง

### สิ่งที่เป็นของต้นแบบเท่านั้น (ไม่มีใน `web/`)

- กรอบหน้าต่างจำลอง, ป้ายทดลองใช้, ปุ่มออกจากห้อง
- ตัวสลับบทบาทและปุ่มอธิบายเครื่องมือบน Mac ในตั้งค่า
- แถบโควตาใช้ไปแล้ว และการ์ดอัปโหลดค้างที่อยู่ในของการ์ดเชิญ (โปรแกรมจริงแยกแผงสถานะ Owner)
- checkbox `-system-preview` ในตั้งค่า (โปรแกรมจริงเป็นธงตอนรัน)
- ข้อความบอก PIN ทดลองบนจอเข้าห้อง

### สิ่งที่ยังไม่เท่าหน้า `web/`

- โปรแกรมจริงฉีดเมนูเชิญและตรวจปัญหาเมื่อเป็น Owner ฉีดตั้งค่า / เกี่ยวกับให้ทุกบทบาท ต้นแบบวางครบใน HTML แล้วซ่อนตามบทบาท
- ลิงก์แขกในโปรแกรมจริงเริ่มต้นปิด จนกดสร้าง
- สลับห้องในต้นแบบยังใช้ชุดไฟล์เดียวกัน โปรแกรมจริงแยกไฟล์/PIN/อุปกรณ์ต่อห้อง
- ภาษาอังกฤษในต้นแบบยังไม่สลับข้อความทั้งหน้า
- QR เป็นกล่องจำลอง ไม่ใช่รูปที่เซิร์ฟเวอร์สร้าง
- รายการอุปกรณ์และสาย USB ในต้นแบบตายตัว โปรแกรมจริงแสดงเครื่องที่ต่ออยู่ตอนนั้น

### วิธีทดลองในต้นแบบโฮสต์ Windows / Android / iOS

ไฟล์ [`mock/ui-mock-hosts.html`](../mock/ui-mock-hosts.html) คือต้นแบบผิว Phase I ของเดิมยังเป็นเว็บ Owner + โปรแกรม Mac ลูกข่ายยังใช้เบราว์เซอร์ ไม่ทำ WebRTC / คลาวด์ / โฮสต์ข้ามอินเทอร์เน็ต สแตก: แกน Go + `web/` เปลือก Windows เป็น Go (`desktop/windows`), Android เป็น Kotlin ห่อ Go (`mobile/android`), iOS เป็น Swift ห่อ Go (`mobile/ios`) (ดูหัวข้อ 4) โค้ดครบ Android และ iOS เทสเส้นหลักบนเครื่องจริงแล้ว Windows ยังไม่มีเครื่องเทส

เมนูเดียวกับ `web/`: เชิญ (Owner), ถ่ายโอน (โฮสต์และผู้ใช้ที่อัปโหลดได้), ไฟล์, ข้อความ, ตรวจปัญหา (Owner), ตั้งค่า, เกี่ยวกับระบบ

- เปิด localhost แล้วเป็น Owner อัตโนมัติ ไม่ต้องใส่ PIN
- สลับ **เทียบทั้งสาม** หรือจอเดียว, **Hotspot / Wi-Fi** (มือถือ อยู่ในช่องเครือข่ายที่ใช้เหมือนเลือกการ์ดบน Mac), แดชบอร์ด / ถาดระบบ
- Windows: ชุดเดียวกับโฮสต์ Mac — ถาดระบบเทียบ menu bar, Explorer เทียบ Finder, ไฟล์บนเครื่องผ่าน ADB
- Android: แดชบอร์ดเดียวกัน ที่เก็บในเครื่องโฮสต์และ USB OTG อยู่ในแท็บไฟล์บนเครื่อง การแจ้งเตือนค้างเทียบ menu bar
- iOS: แดชบอร์ดเดียวกัน แท็บไฟล์บนเครื่องและกลุ่มสาย USB ว่างเพราะไม่มี OTG ไม่ซ่อนเมนู
- แปลง HEIC ด้วย `sips` และพรีวิว `qlmanage` ยังเป็นของโฮสต์ Mac

### วิธีทดลองมุมลูกข่าย

ลูกข่ายใช้หน้า `web/` ชุดเดียวกับโฮสต์ สลับบทบาทใน [`mock/ui-mock-v3.html`](../mock/ui-mock-v3.html) (ตั้งค่า) เพื่อดูเมนูตามสิทธิ์

- Member / Uploader เห็น **ถ่ายโอน** และไฟล์ ไม่เห็นเชิญและตรวจปัญหา
- Viewer ไม่เห็นถ่ายโอนและเชิญ ดาวน์โหลดจากหน้าไฟล์
- ไม่มีจัดการห้อง, ไม่มีแท็บไฟล์บนเครื่อง, ไม่มีตรวจปัญหา — อยู่ที่ Owner

อย่าใช้ Mock แทนการเทสโปรแกรมที่รันจริง (`http://localhost:8080`) เมื่อตรวจอัปโหลด, PIN, USB, หรือสิทธิ์ข้ามห้อง
